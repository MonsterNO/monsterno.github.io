大模型训练全流程拆解-预训练SFT-RLHF的技术细节

约 3648 字大约 12 分钟

大模型训练全流程拆解

2026-09-01

一个大模型从0到1是怎么训练出来的？本文系统拆解大模型训练的三个阶段——预训练（Pre-training）、监督微调（SFT）、人类反馈强化学习（RLHF），讲清每个阶段的目标、数据、方法和工程挑战。

一、大模型训练的三个阶段

一个大语言模型从0到1，通常要经过三个阶段的训练：

  1. 预训练（Pre-training）：在海量无标注文本上训练，让模型学会语言知识和世界知识
  2. 监督微调（Supervised Fine-Tuning, SFT）：在高质量的"指令-回答"数据上微调，让模型学会遵循指令、用对话的方式回答
  3. 人类反馈强化学习（Reinforcement Learning from Human Feedback, RLHF）：用人类的偏好反馈训练一个奖励模型，然后用强化学习让模型生成人类更喜欢的回答

这三个阶段，目标不同、数据不同、方法不同、成本也不同。预训练占了90%以上的成本和时间，SFT和RLHF占了剩下的部分，但对模型的"可用性"至关重要——没有SFT和RLHF的预训练模型，只是一个"文本补全器"，不能很好地和人对话。

下面逐个阶段拆解。

二、预训练：大模型的"基础教育"

预训练是大模型训练的第一阶段，也是最核心、最昂贵的阶段。

2.1 预训练的目标

预训练的目标很简单：让模型学会"根据前面的文本预测下一个词"。

听起来很简单，但就是这个简单的目标，让模型在海量文本上训练后，学到了：

  • 语言知识（语法、词汇、表达方式）
  • 世界知识（事实、常识、历史事件）
  • 推理能力（逻辑、数学、因果推断）
  • 编程能力（代码语法、算法、设计模式）

因为要预测下一个词，模型必须理解前面的内容，并且学到足够的知识才能准确预测。这个"被迫理解"的过程，让模型涌现出了各种能力。

2.2 预训练的数据

预训练需要海量的文本数据。GPT-3的训练数据有45TB文本，LLaMA-2有2万亿Token，DeepSeek-V2有多少万亿Token。

数据来源通常包括：

  • 网页数据：Common Crawl等公开网页数据集，占比最大（通常60-80%）
  • 代码数据：GitHub等开源代码，对编程能力很重要
  • 书籍：高质量的书籍，对知识深度和推理能力有帮助
  • 学术论文：arXiv等学术论文，对专业知识有帮助
  • 百科：维基百科等，对事实知识有帮助
  • 对话数据：论坛、评论等，对对话能力有帮助

数据质量比数据量更重要。 网页数据虽然多，但质量参差不齐——有大量垃圾内容、重复内容、低质量内容。直接用原始网页数据训练，效果不好。所以需要做大量的数据清洗工作：

  • 去重：去掉重复的内容（精确去重和模糊去重）
  • 质量过滤：用分类器或规则过滤掉低质量内容（垃圾邮件、广告、乱码）
  • 有害内容过滤：过滤掉色情、暴力、仇恨等有害内容
  • 语言识别：识别并保留目标语言的内容
  • 数据混合：按一定比例混合不同来源的数据，避免某一类数据占比过大

数据清洗是预训练中最耗时、最需要工程经验的部分。很多团队的训练效果不好，不是模型架构的问题，而是数据质量的问题。

2.3 预训练的方法

预训练的方法就是"下一个词预测"（Next Token Prediction）。具体来说：

  1. 把文本切成固定长度的序列（比如4K或8K Token）
  2. 把序列输入模型，模型预测每个位置的下一个词
  3. 计算预测和真实值的交叉熵损失
  4. 反向传播，更新模型参数

这个过程不断重复，直到模型在验证集上的损失收敛。

2.4 预训练的工程挑战

预训练是一个巨大的工程挑战。一个70B的模型，需要几千张GPU训练几个月。核心挑战包括：

分布式训练：单张GPU放不下一个大模型，需要把模型和数据分布到多张GPU上。常用的技术包括：

  • 数据并行（Data Parallelism, DP）：每张GPU有完整模型，处理不同的数据
  • 张量并行（Tensor Parallelism, TP）：把一层的矩阵运算拆分到多张GPU
  • 流水线并行（Pipeline Parallelism, PP）：把不同层放到不同GPU
  • ZeRO优化：把优化器状态、梯度、参数拆分到不同GPU

训练稳定性：大模型训练很不稳定，经常会出现"损失突增"（Loss Spike）的问题。需要用梯度裁剪、学习率预热、权重衰减等技术来稳定训练。

检查点管理：训练几个月，中间可能会出故障（GPU坏了、网络断了、停电了）。需要定期保存检查点，并且能从检查点恢复训练。

成本控制：几千张GPU跑几个月，成本是几千万甚至上亿。需要精打细算，优化GPU利用率，避免浪费。

三、监督微调（SFT）：让模型学会"听话"

预训练完成后，模型只是一个"文本补全器"——你给它一段文本，它会继续往下写。但它不会"遵循指令"——你问它一个问题，它可能会继续写更多问题，而不是给出答案。

SFT的目标就是：让模型学会遵循人类的指令，用对话的方式回答问题。

3.1 SFT的数据

SFT需要"指令-回答"对（Instruction-Response Pairs）。每条数据包含：

  • 指令（Instruction）：用户的问题或请求
  • 回答（Response）：期望模型给出的回答
  • 可选的上下文（Context）：相关的背景信息

SFT数据的质量要求非常高。因为模型会直接学习这些数据的回答风格和质量。如果SFT数据质量差，模型的效果就会差。

SFT数据的来源通常包括：

  • 人工编写：专门的标注人员编写高质量的指令和回答。质量最高，但成本也最高
  • GPT-4等强模型生成：用强模型生成指令和回答，然后人工筛选。成本较低，质量也不错
  • 真实对话数据：从产品中收集的真实用户对话，经过清洗和脱敏后使用。最贴近真实场景
  • 开源数据集：社区开源的SFT数据集，比如Alpaca、Vicuna、OpenAssistant等

SFT数据的规模通常不需要很大——几万到几十万条高质量数据就够了。关键是质量，不是数量。

3.2 SFT的方法

SFT的方法很简单：在预训练模型的基础上，用SFT数据继续训练，目标还是"下一个词预测"。

和预训练的区别是：

  • 数据不同：SFT用的是"指令-回答"对，而不是无标注文本
  • 学习率不同：SFT用更小的学习率（通常是预训练的1/10），避免破坏预训练学到的知识
  • 训练轮数不同：SFT通常只训练1-3轮，而预训练要训练很多轮
  • 只计算回答部分的损失：指令部分不计算损失，只计算回答部分的损失（这样模型不会去"学习"指令，而是学习怎么回答）

SFT的实现很简单，用普通的语言模型训练代码就能做。关键是数据质量和超参数选择。

3.3 SFT的效果

SFT之后，模型就从"文本补全器"变成了"对话助手"。你问它问题，它会给出答案，而不是继续写问题。

但SFT也有局限性：

  • 模型可能会"迎合"用户——用户说什么它都同意，即使是错的
  • 模型可能会生成冗长、啰嗦的回答
  • 模型可能会编造信息（幻觉）
  • 模型可能不会拒绝有害请求

这些问题，需要RLHF来解决。

四、RLHF：让模型生成人类更喜欢的回答

RLHF（Reinforcement Learning from Human Feedback，人类反馈强化学习）是大模型训练的第三个阶段，目标是让模型生成人类更喜欢的回答。

4.1 为什么需要RLHF

SFT让模型学会了"怎么回答"，但不知道"什么是好的回答"。SFT数据里的回答是标注人员写的，但标注人员之间的标准可能不一致，而且SFT只能学到"标注人员怎么写"，学不到"人类更喜欢什么"。

RLHF的思路是：直接用人类的偏好作为训练信号，让模型学会生成人类更喜欢的回答。

4.2 RLHF的三个步骤

RLHF通常包含三个步骤：

第一步：收集人类偏好数据

让人类标注人员对模型生成的回答进行排序或打分。比如给同一个问题，模型生成了两个回答A和B，标注人员选择哪个更好。

这些偏好数据用来训练奖励模型。

第二步：训练奖励模型（Reward Model, RM）

用人类偏好数据训练一个奖励模型。奖励模型的输入是"问题+回答"，输出是一个分数，表示这个回答有多"好"（人类有多喜欢）。

训练方法是：对于一对回答（A比B好），让奖励模型给A的分数高于B的分数。用排序损失（Ranking Loss）训练。

奖励模型通常是用SFT模型初始化的，然后在偏好数据上微调。它的参数量通常和主模型差不多（或者稍小）。

第三步：用强化学习微调主模型

用奖励模型作为"奖励信号"，用强化学习算法（通常是PPO，Proximal Policy Optimization）微调主模型。

具体过程：

  1. 主模型生成一个回答
  2. 奖励模型给这个回答打分
  3. 用PPO算法更新主模型的参数，让它生成更高分的回答
  4. 同时加一个"KL散度惩罚"，防止模型偏离SFT模型太远（避免为了讨好奖励模型而生成奇怪的内容）

这个过程不断重复，直到模型生成的回答在人类评估中达到满意的水平。

4.3 RLHF的效果和局限

RLHF之后，模型的回答会：

  • 更符合人类的偏好（更有用、更诚实、更无害）
  • 更简洁、更有条理
  • 更愿意拒绝有害请求
  • 更少编造信息

但RLHF也有局限性：

  • 奖励黑客（Reward Hacking）：模型可能会找到"欺骗"奖励模型的方法——生成奖励模型喜欢但人类其实不喜欢的内容（比如过度讨好、过度道歉）
  • 对齐税（Alignment Tax）：RLHF可能会让模型的能力略有下降（比如推理能力、知识广度），因为它在"讨好人类"而不是"追求正确"
  • 人类偏好的主观性：不同人的偏好不一样，标注人员之间的标准可能不一致
  • 成本高：收集人类偏好数据、训练奖励模型、PPO训练，成本都很高

4.4 RLHF的替代方案

因为RLHF成本高、实现复杂，社区也在探索替代方案：

DPO（Direct Preference Optimization）：直接用偏好数据优化模型，不需要训练奖励模型，也不需要PPO。实现更简单，效果也不错。现在很多开源模型用DPO代替RLHF。

RLAIF（Reinforcement Learning from AI Feedback）：用AI的反馈代替人类反馈，降低成本。比如用GPT-4给回答打分，作为奖励信号。

拒绝采样（Rejection Sampling）：让模型生成多个回答，用奖励模型或人类选择最好的那个，然后用SFT的方法训练。简单有效，很多模型用这个方法代替RLHF。

五、训练后的评估

训练完成后，需要对模型进行全面的评估。评估通常包括几个维度：

能力评估：

  • 知识：MMLU（多任务语言理解）、TriviaQA（问答）等
  • 推理：GSM8K（数学）、HumanEval（代码）、BBH（大困难任务）等
  • 语言：翻译、摘要、写作等
  • 对话：MT-Bench（多轮对话）、人工评估等

安全评估：

  • 有害内容生成
  • 偏见和歧视
  • 隐私泄露
  • 越狱（Jailbreak）抵抗能力

人类评估：

  • 有用性（Helpfulness）
  • 诚实性（Honesty）
  • 无害性（Harmlessness）
  • 整体满意度

评估是大模型训练的重要环节。没有评估，你就不知道训练效果好不好，也不知道下一步该怎么优化。

六、总结

大模型训练是一个复杂的系统工程，三个阶段各有侧重：

阶段目标数据方法成本占比
预训练学会语言和世界知识海量无标注文本下一个词预测~90%
SFT学会遵循指令和对话高质量指令-回答对监督微调~5%
RLHF学会生成人类喜欢的回答人类偏好数据奖励模型+PPO~5%

几个关键洞察：

  1. 数据是核心：三个阶段的效果，最终都取决于数据质量。预训练的数据清洗、SFT的数据质量、RLHF的偏好数据标准，都是决定模型效果的关键。
  2. 预训练是基础：预训练决定了模型的"能力上限"，SFT和RLHF只是在这个上限内做"对齐"。如果预训练没学好，后面再怎么微调也没用。
  3. 对齐是持续的：SFT和RLHF不是一次性的，需要持续迭代。根据用户反馈，不断优化SFT数据和偏好数据，让模型越来越好用。
  4. 工程是关键：大模型训练不仅是算法问题，更是工程问题。分布式训练、稳定性、成本控制、评估体系，这些工程能力往往决定了训练的成败。

大模型训练的门槛很高——需要大量的数据、大量的GPU、大量的工程经验。但随着开源生态的发展（LLaMA、Qwen、DeepSeek等开源模型，以及各种训练框架），门槛在逐渐降低。未来，会有越来越多的团队能训练自己的大模型。
