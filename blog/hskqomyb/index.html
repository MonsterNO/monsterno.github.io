让AI记住你-Agent记忆系统设计

约 2225 字大约 7 分钟

AI智能体

2026-09-01

没有记忆的AI每次对话都是从零开始。本文从实际项目出发，拆解Agent记忆系统的三种类型，用代码实现一个可落地的记忆模块，并聊聊记忆带来的隐私与成本问题。

我做过一个客服Agent，上线第一周用户反馈最多的问题不是回答不准，而是"它怎么每次都不记得我"。

有个用户连续三天来问同一个订单的问题，每次都要重新报订单号、重新说明情况。到第三天他终于忍不住了："你们这个AI是不是有健忘症？我昨天刚说过的事今天又要再说一遍？"

这个问题让我意识到，Agent和普通聊天机器人最大的区别，不是它能调用多少工具，而是它有没有记忆。没有记忆的Agent，每次对话都是第一次见面，永远无法建立真正的"关系"。

但给Agent加记忆这件事，听起来简单，做起来全是坑。

记忆的三种类型

做记忆系统之前，得先想清楚你要的是哪种记忆。我把它分成三类：

短期记忆（Short-term Memory）：当前对话轮次内的上下文。比如用户上一句说"帮我查订单"，这一句说"那个订单发货了吗"，AI需要知道"那个订单"指的是什么。这本质上就是对话历史，最简单的实现方式就是把历史消息全部塞进上下文窗口。

长期记忆（Long-term Memory）：跨会话的用户信息。比如用户的名字、偏好、历史订单、之前聊过的话题。这些信息不能全塞上下文（会爆），需要单独存储，在需要时检索出来。这是本文重点要讲的。

情景记忆（Episodic Memory）：对具体事件的记忆。比如"上周三用户因为物流延迟投诉过"，这是一个完整的事件，包含时间、人物、经过、结果。情景记忆比简单的用户画像更丰富，能让AI在合适的时候"想起"相关的事。

大部分人说"给Agent加记忆"，指的是长期记忆。下面我们就来实现一个。

动手实现一个记忆模块

核心思路是：用户每说一句话，就从中提取关键信息存入记忆库；AI回答之前，先从记忆库检索和当前问题相关的记忆，注入到提示词里。

我们用向量数据库做记忆存储，这里用Chroma（轻量、本地可跑）：

pip install chromadb openai

创建memory_module.py：

import chromadb
from openai import OpenAI
import uuid
from datetime import datetime

client = OpenAI(api_key="your-api-key")

# 初始化Chroma向量数据库
chroma_client = chromadb.PersistentClient(path="./memory_db")
collection = chroma_client.get_or_create_collection(
    name="user_memories",
    metadata={"hnsw:space": "cosine"}
)

def get_embedding(text):
    """获取文本的向量表示"""
    response = client.embeddings.create(
        model="text-embedding-3-small",
        input=text
    )
    return response.data[0].embedding

def store_memory(user_id, content, memory_type="fact"):
    """存储一条记忆
    
    Args:
        user_id: 用户标识
        content: 记忆内容
        memory_type: 记忆类型，fact(事实)/preference(偏好)/event(事件)
    """
    embedding = get_embedding(content)
    collection.add(
        ids=[str(uuid.uuid4())],
        embeddings=[embedding],
        documents=[content],
        metadatas=[{
            "user_id": user_id,
            "type": memory_type,
            "timestamp": datetime.now().isoformat()
        }]
    )

def retrieve_memories(user_id, query, top_k=5):
    """检索和当前问题相关的记忆
    
    Args:
        user_id: 用户标识
        query: 当前用户输入
        top_k: 返回最相关的记忆条数
    """
    query_embedding = get_embedding(query)
    results = collection.query(
        query_embeddings=[query_embedding],
        n_results=top_k,
        where={"user_id": user_id}
    )
    
    if not results["documents"][0]:
        return ""
    
    memories = []
    for doc, meta in zip(results["documents"][0], results["metadatas"][0]):
        memories.append(f"- [{meta['type']}] {doc}")
    
    return "\n".join(memories)

def extract_and_store(user_id, user_input, ai_response):
    """从对话中提取关键信息并存入记忆
    
    这是记忆系统最核心的部分：不是所有对话都值得记，
    需要让AI判断哪些信息值得存储。
    """
    prompt = f"""请从以下对话中提取值得长期记忆的用户信息。
    只提取明确的事实、偏好和重要事件，不要推测。
    
    用户说：{user_input}
    AI回复：{ai_response}
    
    请按以下格式输出（每行一条，没有就输出"无"）：
    FACT: 明确的事实信息（如"用户叫张三"）
    PREFERENCE: 用户偏好（如"用户喜欢简洁的回复"）
    EVENT: 重要事件（如"用户投诉了订单延迟"）
    """
    
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        temperature=0
    )
    
    lines = response.choices[0].message.content.strip().split("\n")
    for line in lines:
        if line.startswith("FACT:"):
            store_memory(user_id, line[5:].strip(), "fact")
        elif line.startswith("PREFERENCE:"):
            store_memory(user_id, line[11:].strip(), "preference")
        elif line.startswith("EVENT:"):
            store_memory(user_id, line[6:].strip(), "event")

然后在Agent的对话流程中使用：

def chat(user_id, user_input):
    # 1. 检索相关记忆
    memories = retrieve_memories(user_id, user_input)
    
    # 2. 构建带记忆的提示词
    system_prompt = "你是一个贴心的客服助手。"
    if memories:
        system_prompt += f"\n\n以下是关于该用户的历史记忆，请参考：\n{memories}"
    
    # 3. 调用大模型
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": user_input}
        ]
    )
    ai_response = response.choices[0].message.content
    
    # 4. 从本轮对话中提取记忆并存储
    extract_and_store(user_id, user_input, ai_response)
    
    return ai_response

整个流程就四步：检索记忆 → 注入提示词 → 生成回复 → 提取新记忆。跑起来之后，你会发现AI真的开始"记住"用户了。

几个关键的设计决策

写记忆系统的过程中，有几个问题是绕不开的：

什么该记，什么不该记？ 这是最核心的问题。如果什么都记，记忆库会迅速膨胀，检索出来的全是噪音；如果记太少，又达不到效果。我的做法是用上面的extract_and_store函数，让AI自己判断哪些值得记，并且只记明确的事实、偏好和事件，不记推测。另外定期清理——超过6个月没被检索到的记忆，自动归档或删除。

记忆冲突了怎么办？ 用户之前说"我是做前端的"，后来又说"我转岗做后端了"，两条记忆矛盾。这时候需要做记忆更新：新记忆覆盖旧记忆，而不是简单追加。实现方式是在存储前先检索相似记忆，如果发现冲突，就把旧记忆标记为"已更新"。这个功能我目前是手动处理的，自动化还在探索。

检索多少条合适？ top_k=5是我的经验值。太少了信息不够，太多了会挤占上下文窗口，而且容易引入不相关的记忆。另外我会按记忆类型加权：偏好类记忆权重最高（因为直接影响回复方式），事实类次之，事件类最低。

隐私怎么处理？ 记忆里存的是用户的个人信息，这是敏感数据。我的建议是：第一，用户有权查看和删除自己的记忆（GDPR风格）；第二，不要存密码、身份证号这类敏感信息，提取时要过滤；第三，记忆库要加密存储。

我的一些思考

做记忆系统的过程中，我最大的感受是：记忆不是技术问题，是产品问题。

技术上，向量数据库+语义检索已经很成熟了，实现一个基础版记忆模块也就一百行代码。难的是决定"记什么、什么时候用、用多少"——这些都是产品决策，需要你对用户场景有深刻理解。

比如客服场景，用户的历史投诉记录是最重要的记忆，因为它直接影响当前回复的语气和策略。但在写作助手场景，用户的历史投诉就毫无意义，反而用户的写作风格偏好才是关键。不同场景需要的记忆完全不同，没有通用方案。

另一个让我深思的点是：记忆会改变AI的"性格"。当AI记住了用户的偏好、习惯、过往经历，它的回复就不再是标准化的，而是"针对这个人"的。这种个性化体验，才是Agent真正的护城河——通用大模型谁都能调用，但你积累的用户记忆，是别人抄不走的。

当然记忆也有风险。AI记错了比不记更糟糕——如果它记错了用户的名字，或者把A用户的记忆用到B用户身上，那体验是灾难性的。所以记忆系统的准确率比覆盖率重要得多。宁可少记，也不要记错。

如果你也在做Agent，建议尽早加记忆。不用一开始就搞很复杂，就从最简单的用户偏好记忆开始——比如记住用户喜欢简洁回复还是详细回复。这一个小改动，用户体验就能上一个台阶。然后再逐步扩展到事实记忆、事件记忆。

AI有了记忆，才真正从"工具"变成了"助手"。工具是用完就忘的，助手是记得你的。
