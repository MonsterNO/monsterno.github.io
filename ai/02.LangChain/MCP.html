MCP ​

概念 ​

MCP（Model Context Protocol）是 Anthropic 推出的开放标准，用来把 AI 应用接到外部系统上：文件、搜索、地图、航班、天气，只要服务方能按 MCP 提供能力，AI 就能用。

打个比方，MCP 就是 AI 世界的 USB 接口协议：

  • 所有外部服务的提供方都可以按 MCP 协议把自己的 Tool 分享出来，不用管谁来接；
  • AI 应用按 MCP 协议去对接，不用为每个服务单独写 Tool 定义。

三个角色各管一段：

概念描述
MCP Server提供 MCP 服务的应用，可以是远程服务，也可以是本地服务
MCP Client连接到 Server，读取 MCP 信息（尤其是 Tool 信息），交给 Host
MCP Host协调和管理多个 Client 的 AI 应用，比如 LangChain 的 Agent

有什么用 ​

没有 MCP 的时候，想让 AI 连外部系统，只能自己一个个定义 tool：文件操作、web 搜索、查航班、查天气，每个都得写名字、参数、调用逻辑。这带来两个绕不开的问题：

  • 不同 Agent 往往有同样的 tool 需求，每次都重复定义，复用性差；
  • 全世界有各种服务，接口各不相同，逐个定义 tool 非常麻烦。

MCP 把这两件事一起解决：

场景解决什么
工具复用同一个 Server 的 Tool，任何支持 MCP 的 Agent 都能直接用
接入成本接一个新服务只写一段配置，不用写 tool 定义和参数 schema
生态开放云厂商自己维护 Server，能力升级不用改你的代码
跨应用同一套 Server，Claude Desktop、Cursor、LangChain Agent 都能接
边界清晰本地能力走 stdio 子进程，云能力走 http，权限范围一目了然

所以：MCP 不生产工具，它只是让工具“即插即用”。

通信协议 ​

MCP 规定了两种传输方式：

协议描述
stdio标准输入输出，Client 把 Server 作为子进程拉起
streamable_http基于 HTTP：Client 发 POST，Server 可用 SSE 流式返回

stdio 是标准输入输出，Client 运行时按两种情况处理：

  • 外部服务：Client 把该 MCP 服务的脚本下载到本地，作为一个子进程运行；
  • 本地服务：Client 直接加载本地脚本，作为一个子进程运行。

也就是说，stdio 模式下 Client 与 Server 之间就是进程间通信，没有网络延迟。

streamable_http 本质是 HTTP 请求：Client 用 POST 把调用发出去，Server 可以用 Server-Sent Events（SSE）把结果流式推回来。因为每次都要走网络，所以存在一定延迟。

两种传输的取舍：

传输延迟部署典型用途
stdio无网络延迟本机装好运行环境文件、时间、本地脚本类工具
streamable_http有网络延迟服务方托管，可远程调地图、航班、云 SaaS 类服务

去哪找 MCP 服务 ​

很多提供云服务的公司都发布了 MCP Server，比如：

  • Amap Maps：高德地图的 MCP
  • Filesystem：操作文件系统的 MCP
  • Time：查询当前时间、做时区转换的 MCP
  • Kiwi：查询航班、预订航班的 MCP

想要更多就去魔塔社区搜——它是一个 MCP 服务社区，可以搜索、使用、分享各种 MCP Server。

安装与配置 ​

安装依赖 ​

LangChain 通过适配器使用 MCP，先装它：

bash
uv add langchain-mcp-adapters
1

谁来拉起 Server：npx 与 uvx ​

stdio 模式下，Server 是本地子进程，谁把它拉起来取决于配置里的 command，常见两种：

  • npx：Node.js 的包管理器，用来跑 npm 上的 MCP 包；
  • uvx：Python 的 uv 工具链，用来跑 PyPI 上的 MCP 包。

所以本机必须能执行 npx 或 uvx——这是 stdio 模式能跑起来的前提，先 npx -v、uvx --version 验一下。

另外，LangChain 的配置比标准 MCP 配置多一个必填字段 transport，用来指定传输方式，取值为 stdio 或 http（streamable_http）。

两份配置对照着看最清楚。标准 MCP 的写法：

json
{
  "mcpServers": {
    "time-mcp": {
      "args": ["-y", "time-mcp"],
      "command": "npx"
    }
  }
}

实战案例 ​

实战分两种：一是接别人做好的 MCP（大多数场景就是这样），二是把自己的函数做成 MCP。前者验证“能不能连上”，后者验证“怎么把一段普通代码包成 Tool”。

案例一：接入现成的 Time MCP ​

目标：接一个基于 stdio 的 Time MCP，让 Agent 能回答“现在几点”，并验证工具确实被加载。

Time 是一个提供时间与时区转换的 MCP：能让 LLM 获取当前时间，用 IANA 时区名做转换，还能自动检测系统时区，详见使用方法。

配置要点：它是 stdio 通信，脚本靠 npx 下载到本地后作为子进程运行，所以配置里写 command: npx、transport: stdio。

python
import asyncio

from dotenv import load_dotenv
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain_core.messages import HumanMessage
from langchain_mcp_adapters.client import MultiServerMCPClient

load_dotenv()


async def main():
    # 直接实例化，不再套 async with
    client = MultiServerMCPClient(
        {
            "time-mcp": {
                "transport": "stdio",
                "command": "npx",
                "args": [
                    "-y",
                    "time-mcp"
                ]
            }
        }
    )

    # await 拿到全部 MCP 工具
    tools = await client.get_tools()
    print(f"✅ 成功加载 MCP 工具，数量：{len(tools)}")

    # 模型
    model = init_chat_model(
        model="deepseek-v4-flash",
        extra_body={"thinking": {"type": "disabled"}}
    )

    # 创建 Agent，tools 直接来自 MCP
    agent = create_agent(
        model=model,
        tools=tools
    )

    # 异步调用
    result = await agent.ainvoke(
        {"messages": [HumanMessage("现在是什么时间")]}
    )

    # 打印完整消息流
    for msg in result["messages"]:
        print(f"\n【{msg.type}】: {msg.content}")


if __name__ == "__main__":
    asyncio.run(main())

案例二：自己写一个两数相加的 MCP ​

目标：写一个最小 MCP Server，暴露一个 add(a, b) 工具，再让 LangChain 的 Agent 调用它。

自己写 MCP 用官方 Python SDK 里的 FastMCP：一个普通函数加一个装饰器，就是 Tool。

  1. 装依赖
bash
uv add mcp langchain-mcp-adapters
1
  1. 写 Server：calc_server.py
python
from mcp.server.fastmcp import FastMCP

# 服务名，只用于标识自己
mcp = FastMCP("calc-mcp")


@mcp.tool()
def add(a: int, b: int) -> int:
    """计算两个整数之和。"""
    return a + b


if __name__ == "__main__":
    mcp.run()   # 默认走 stdio，等 Client 来拉起

三个细节决定它能不能被模型正确调用：

  • 类型标注（a: int, b: int）会被转成工具的入参 schema，省了就变成无参工具，模型没法传数进来；
  • docstring 会被转成工具描述，是模型判断“该不该调这个工具”的依据，别留空；
  • mcp.run() 默认就是 stdio，正好对应 Client 配置里的 transport: stdio。
  1. 接进 Agent：client.py
python
import asyncio

from dotenv import load_dotenv
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain_core.messages import HumanMessage
from langchain_mcp_adapters.client import MultiServerMCPClient

load_dotenv()


async def main():
    client = MultiServerMCPClient(
        {
            "calc-mcp": {
                "transport": "stdio",
                "command": "uv",                    # 用 uv 起 Python 子进程
                "args": ["run", "calc_server.py"],
            }
        }
    )

    # 工具名与描述都来自 Server 里的函数名和 docstring
    tools = await client.get_tools()
    for t in tools:
        print(t.name, "-", t.description)

    model = init_chat_model(
        model="deepseek-v4-flash",
        extra_body={"thinking": {"type": "disabled"}}
    )
    agent = create_agent(model=model, tools=tools)

    result = await agent.ainvoke(
        {"messages": [HumanMessage("帮我算一下 12 加 30 等于多少")]}
    )
    for msg in result["messages"]:
        print(f"\n【{msg.type}】: {msg.content}")


if __name__ == "__main__":
    asyncio.run(main())

验证点：

  • 打印出 add - 计算两个整数之和。，说明自定义 Server 被成功拉起，入参 schema 和描述都读到了；
  • 消息流里出现一条 tool 消息，content 是 42；
  • 最后一条 ai 消息把 42 用人话讲出来。

所以：写一个 MCP 的成本就是“一个函数 + @mcp.tool() + mcp.run()”。手上的老代码想让 AI 用，包一层就能接进去。

没装 uv 的话，Client 配置改成 "command": "python"、"args": ["calc_server.py"] 也行，只要 mcp 装在这个解释器里。

注意事项 ​

  1. 本机没有 npx / uvx —— 现象：工具数量为 0，或报 FileNotFoundError。原因：stdio 模式要靠 command 拉起子进程，命令不存在就起不来。解法：装 Node.js（自带 npx）或 uv（自带 uvx），先 npx -v / uvx --version 验证。
  2. Windows 上 command: "npx" 起不来 —— 现象：报 WinError 2 或找不到文件。原因：Windows 下的 npx 是 .cmd 批处理，不能直接当可执行文件启动。解法：写 "command": "cmd"，"args": ["/c", "npx", "-y", "time-mcp"]。
  3. 漏写 transport —— 现象：抛 KeyError 或直接报配置校验失败。原因：直接从魔塔社区抄来的标准 MCP 配置里没有这个字段，而 LangChain 必填。解法：补上 "transport": "stdio" 或 "transport": "http"。
  4. 照老教程写 async with MultiServerMCPClient(...) —— 现象：报不支持上下文管理器。原因：新版直接实例化，连接在 get_tools() / 调用工具时才建立。解法：client = MultiServerMCPClient({...})，然后 await client.get_tools()。
  5. 忘了 await get_tools() —— 现象：len(tools) 报错，或 Agent 收到的 tools 是个协程对象。原因：get_tools 是异步方法。解法：tools = await client.get_tools()，整段逻辑放在 async def 里用 asyncio.run() 跑。
  6. streamable_http 连不上 —— 现象：报 401 或连接超时。原因：远端 Server 大多要鉴权 header，或者地址填成了旧的 SSE 路径。解法：按服务商文档在配置里补 headers，并用它给的 streamable_http 端点地址。
  7. 在自己写的 Server 里 print 调试 —— 现象：Client 报报文解析错误、工具加载失败，或者干脆卡住。原因：stdio 模式下 stdout 就是协议通道，print 的内容会混进 JSON-RPC 报文，把协议打乱。解法：调试信息写 stderr（print(..., file=sys.stderr)）或直接用 logging，它默认就输出到 stderr。

总结 ​

  • MCP 是 AI 世界的 USB 协议：Server 提供能力，Client 读工具，Host（Agent）把工具交给模型。
  • 传输只有两种：本地能力用 stdio（子进程，无网络延迟），云能力用 streamable_http（HTTP，有延迟）。
  • LangChain 里接 MCP：uv add langchain-mcp-adapters → 写 MultiServerMCPClient 配置（别忘 transport）→ await client.get_tools() → 塞给 create_agent。
  • command 决定谁来拉起 Server：npx 跑 npm 包，uvx 跑 PyPI 包，本机必须装好对应工具。
  • 接新服务优先去魔塔社区搜，找到现成的 Server 比自己写 tool 便宜得多。
  • 自己的函数要变成 Tool，用 FastMCP 包一层：@mcp.tool() + mcp.run()，函数名和 docstring 就是工具名和描述。
  • 自己写 Server 时别用 print 调试，stdout 是协议通道，日志要走 stderr。
