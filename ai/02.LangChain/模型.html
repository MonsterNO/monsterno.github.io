模型（Models） ​

概念 ​

模型（Model，代码里叫 ChatModel）是 LangChain 对大模型客户端的一层统一封装。不管是 DeepSeek、通义千问还是本地 Ollama，进到 LangChain 里都是同一个 ChatModel 对象，都有同一套 invoke / stream 方法、同一套消息格式。

围绕它只有四件事：

  • 初始化：把「哪个厂商、哪个模型、用什么 key」变成一个 model 对象
  • 直接调用：model.invoke(...) 拿一次回答
  • 消息：把 dict 换成 HumanMessage、SystemMessage 这类统一对象
  • 结构化输出：让模型不返回自由文本，直接返回一个 Pydantic 对象

快速入门里 create_agent(model="deepseek-v4-flash") 传的是字符串，LangChain 内部帮你初始化了模型，所有参数都吃默认值。想改 temperature、想加 extra_body，就得自己把模型初始化出来。

有什么用 ​

直接对接各家 SDK 会碰到的麻烦，模型封装基本都挡住了：

你遇到的问题模型封装给的东西
每家 SDK 参数名、调用方式都不一样统一用 init_chat_model，换模型只改一个字符串
想调 temperature 却没地方传参数表一次配齐，包括 max_tokens、penalty 等
换个厂商就得重写调用代码拿到手都是 ChatModel，下游代码不用动
拼 {"role": "user", ...} 太啰嗦用 HumanMessage 等消息类，类型明确
模型返回一段 JSON 还得自己解析、校验with_structured_output 直接返回 Pydantic 对象
只为了一次问答却要建 Agent简单业务直接 model.invoke，不必上 Agent

一句话：模型负责「说」，Agent 负责「决定怎么做」。只说话的场景，直接用模型就够。

初始化模型 ​

LangChain 给了三条路，最后拿到的都是同一种 ChatModel：

init_chat_model 的常用参数：

参数说明必填
model模型名称是
model_provider模型提供方，如 openai、deepseek、anthropic；不填则按模型名前缀推断否
api_key密钥，不填则从环境变量读（OPENAI_API_KEY、DEEPSEEK_API_KEY 等）否
base_url接口地址，第三方代理或自建网关时用否
temperature温度，越高越发散否
max_tokens单次输出上限否
presence_penalty话题新鲜度惩罚否
frequency_penalty重复词惩罚否

参数虽多，实际只分两种情况：默认初始化只需要 model；自定义初始化要把 model_provider、base_url、api_key 一起给。

默认初始化 ​

适用于 LangChain 已支持的模型。给个 model 名，model_provider、base_url 由它推断，api_key 从环境变量读。

以 DeepSeek 为例，三步走：

  1. 装依赖（已装可跳过）
bash
uv add langchain-deepseek
1
  1. 在 .env 里放 key
bash
DEEPSEEK_API_KEY=
1
  1. 初始化并试跑
python
# ===================1.初始化模型=====================
from langchain.chat_models import init_chat_model
from dotenv import load_dotenv
load_dotenv()

# LangChain 自动推断 base_url 和 api_key，这里只给想改的参数
model = init_chat_model(
    model="deepseek-v4-flash",
    temperature=0.7,
    extra_body={"thinking": {"type": "disabled"}},
)

# =================2.测试====================
from langchain.agents import create_agent

agent = create_agent(model=model, tools=[])

result = agent.invoke({"messages": [{"role": "user", "content": "你是谁？"}]})
print(result)

自定义初始化 ​

LangChain 不认识的模型，就得自己把 model_provider、base_url、api_key 交代清楚。

以阿里云百炼的 qwen 为例——它不在支持列表里，但兼容 OpenAI 规范：

  1. .env 里配 key 和地址
bash
DASHSCOPE_API_KEY=
DASHSCOPE_BASE_URL=
1
2
  1. 手动读出环境变量，传给 init_chat_model
python
from langchain.chat_models import init_chat_model

# ===================Step 1.初始化模型=====================
from dotenv import load_dotenv
load_dotenv()

import os

base_url = os.getenv("DASHSCOPE_BASE_URL")
api_key = os.getenv("DASHSCOPE_API_KEY")

model = init_chat_model(
    model="qwen3.7-plus",        # 模型名称
    model_provider="openai",     # 不被支持但兼容 OpenAI 规范的，都填 openai
    base_url=base_url,
    api_key=api_key,
)

# =================Step 2.测试====================
from langchain.agents import create_agent

agent = create_agent(model=model, tools=[])

result = agent.invoke({"messages": [{"role": "user", "content": "你是谁？"}]})
print(result)

专用 Model 类 ​

既不兼容 OpenAI 规范、也不被 init_chat_model 支持的厂商，只能用它自己的 Model 类。Ollama 就是典型。

  1. 装依赖
bash
uv add langchain-ollama
1
  1. 用 ChatOllama 直接建对象，本地部署的模型都能连
python
from langchain_ollama import ChatOllama

model = ChatOllama(
    model="qwen3.5:0.8b",
    temperature=1.0,
)

# =================测试====================
from langchain.agents import create_agent

agent = create_agent(model=model, tools=[])

result = agent.invoke({"messages": [{"role": "user", "content": "你是谁？"}]})
print(result)

三种方式怎么选 ​

情况用哪种要填什么
厂商在 LangChain 支持列表里默认初始化model（+ 想改的参数）
不在列表，但兼容 OpenAI 协议自定义初始化model、model_provider="openai"、base_url、api_key
协议也不兼容（如 Ollama）专用 Model 类该类的构造参数

判断顺序就一句：先看列表，再看协议，最后才用专用类。

直接调用模型 ​

不是为了省事而省事——只有一次性问答、不需要工具和循环时，建 Agent 纯属浪费。

LangChain 给了两个入口：

  • invoke：阻塞，等全部算完返回
  • stream：流式，边生成边返回

常见用法还是 invoke：

python
from langchain.chat_models import init_chat_model
from dotenv import load_dotenv
load_dotenv()

model = init_chat_model(
    model="deepseek-v4-flash",
    extra_body={"thinking": {"type": "disabled"}},
)

# 直接传字符串也可以
result = model.invoke("你是谁？")
print(result)

消息（Messages） ​

调模型时，发出去的和收回来的都是消息。一条消息由三部分组成：

部分说明
role角色：system、user、assistant、tool
content正文内容
metadata可选，如消息 ID、token 消耗等

之前用 dict 模拟消息：

python
response = model.invoke([{"role": "user", "content": "你是谁？"}])
1

能跑，但字段全靠手写，拼错 role 也不报错。LangChain 把消息统一封装成 BaseMessage，它是整个上下文的基本单元。

消息类型 ​

类型对应 role谁产生的
HumanMessageuser用户输入
AIMessageassistant模型输出
SystemMessagesystem系统提示词，定角色和背景
ToolMessagetool工具执行结果，回传给模型

定义消息 ​

python
from langchain.messages import HumanMessage, SystemMessage
from langchain.chat_models import init_chat_model
from dotenv import load_dotenv
load_dotenv()

model = init_chat_model(
    model="deepseek-v4-flash",
    extra_body={"thinking": {"type": "disabled"}},
)

result = model.invoke([
    SystemMessage(content="你扮演柯南，用他的身份回答问题"),
    HumanMessage(content="你是谁？"),
])

print(result)

结构化输出 ​

需要模型返回固定结构（而不是一段自由文本）时，不用自己解析 JSON——把 Pydantic 类丢给 with_structured_output，返回的就是对象。步骤是：

  1. 读环境变量
  2. 初始化普通模型
  3. 用 pydantic.BaseModel 定义想要的字段
  4. model.with_structured_output(schema=...) 绑定
  5. 调用，拿到对象
python
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain.messages import HumanMessage
load_dotenv()

model = init_chat_model(
    model="deepseek-v4-flash",
    extra_body={"thinking": {"type": "disabled"}},
)

# 3.定义 BaseModel，既约束输出，也承接数据
from pydantic import BaseModel, Field

class CapitalInfo(BaseModel):
    name: str = Field(description="城市的名字")
    eat: str = Field(description="城市里的美食")
    play: str = Field(description="城市里的活动")

# 4.绑定，得到一个会输出结构的新模型对象
model_with_structured_output = model.with_structured_output(schema=CapitalInfo)

# 5.调用
result = model_with_structured_output.invoke([HumanMessage("广州一日游攻略")])

print(type(result))  # <class '__main__.CapitalInfo'>
print(result)

注意事项 ​

  1. 忘了 load_dotenv()。最常见的报错就是这个，模型初始化时会提示找不到对应的 _API_KEY，key 明明写在 .env 里，只是没加载。
  2. 默认初始化漏装厂商包。init_chat_model("deepseek-...") 会去找 langchain-deepseek，没装就会在推断 provider 时直接报错，先 uv add 再初始化。
  3. 自定义初始化时 model_provider 填错。这里填的是协议不是厂商，兼容 OpenAI 的第三方一律填 "openai"，别填成 "qwen" 之类厂商名。
  4. model 名字决定推断结果。前缀不认识（或拼错）时，model_provider 推断失败，宁可显式写死 model_provider。
  5. 字段 description 别写得太含糊。它是模型填值的依据，数字字段一定要写单位和口径，否则「一年半」可能被填成 1。
  6. with_structured_output 返回的是新对象。原 model 没被修改，还想拿自然语言回答就继续用 model.invoke。

实战案例 ​

目标：从一段口语化的自我介绍里抽出结构化简历——姓名、技能列表、带嵌套的工作经历，验证嵌套结构也能正常转对象。

python
from dotenv import load_dotenv
from pydantic import BaseModel, Field
from langchain.chat_models import init_chat_model
from langchain.messages import HumanMessage

load_dotenv()

class Job(BaseModel):
    company: str = Field(description="公司名称")
    years: float = Field(description="在职时长，单位年，不满一年按小数算")

class Resume(BaseModel):
    name: str = Field(description="候选人姓名")
    skills: list[str] = Field(description="技能关键词列表，只保留技术名词")
    jobs: list[Job] = Field(description="工作经历列表，按时间倒序")

model = init_chat_model(
    model="deepseek-v4-flash",
    extra_body={"thinking": {"type": "disabled"}},
)

# 绑定 schema，得到会输出 Resume 的新对象
parser = model.with_structured_output(schema=Resume)

text = "我叫詹昌健，前端开发工程师，做过 Vue3、FastAPI、Docker，在卡姿兰干了 2 年，之前在另一家小公司做了 1 年半。"

result = parser.invoke([HumanMessage(f"从这段自我介绍里抽取简历信息：\n{text}")])

print(type(result))
print(result.name, result.skills)
for job in result.jobs:
    print(job.company, job.years)

三个值得注意的点：

  • result 已经是 Resume 实例，skills 直接是 Python 列表，不用再 json.loads
  • 嵌套的 jobs 里每一项都是 Job 对象，job.years 是 float 而非字符串
  • 「一年半」被正确转成 1.5，靠的就是 years 字段里那句「单位年，不满一年按小数算」——description 写不写清楚，直接决定这一步准不准

总结 ​

  • ChatModel 是大模型的统一外壳：一套初始化参数、一套消息格式、一套调用方法，换厂商只改初始化那几行。
  • 初始化三条路：支持列表内用默认初始化；兼容 OpenAI 协议用自定义初始化（model_provider="openai"）；都不行才用专用 Model 类。
  • 简单业务直接 model.invoke，一次问答不需要 Agent；要工具、要循环、要记忆才上 Agent。
  • 消息用 HumanMessage、SystemMessage 这类对象代替手写 dict，角色和内容都带类型。
  • with_structured_output 让模型直接返回 Pydantic 对象，字段 description 写得越具体，结果越可靠。
