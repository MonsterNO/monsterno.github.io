Agent调用 ​

概念 ​

Agent 调用，指的是把一句用户输入交给 create_agent 建好的 Agent，让它自己跑完「思考 → 调工具 → 再思考」这一圈，最后把结果拿回来。

它和直接调模型最大的区别在入参和出参的形状：

  • 入参是一个 dict，唯一必需的 key 是 messages，值是消息列表
  • 出参也是一个 dict，里面的 messages 是从头到尾的完整对话记录，包括中间的每一条 tool 消息
  • 最终答案在 result["messages"][-1]，不在 result["content"]

调用方式有两种：

方式行为适合
invoke阻塞，等全部算完一次性返回脚本、后台任务、批处理
stream_events边跑边吐，可以逐条、逐片段拿到聊天界面、需要实时反馈

有什么用 ​

如果只会直接调模型，你会遇到这几个问题，而 Agent 调用正好各补一块：

你遇到的问题Agent 调用给的东西
模型不能自己查数据库、调接口tools 交给 Agent，由它决定调不调、调几次
每轮都要手动拼 SystemMessagesystem_prompt 在创建时设一次，之后自动带上
用户盯着空屏幕等十几秒stream_events 边生成边显示，首字很快出现
想知道中间到底调了什么工具返回的 messages 里保留了每条 ToolMessage
下一轮对话要接上上文checkpointer 自动存取历史（见记忆）

简单说：模型负责说话，Agent 负责决定该不该动手、动几次手，以及把过程记下来。

创建 Agent 的五个步骤 ​

所有调用方式共用这套前置流程：

  1. 加载环境变量（load_dotenv()）
  2. 初始化模型（init_chat_model(...)）
  3. 用 @tool 定义工具
  4. create_agent(model=..., tools=...) 建出 Agent
  5. 调用（invoke 或 stream_events）

create_agent 常用参数：

参数类型说明
modelBaseChatModel 或字符串必填，Agent 的大脑
toolslist[BaseTool]不传就是空列表，此时只能聊，不算完整 Agent
system_promptstr角色与背景设定，创建时定好
checkpointerBaseCheckpointSaver加上就有多轮记忆
middlewarelist在循环里插钩子，做拦截、改写等进阶操作

invoke：一次性拿到完整结果 ​

python
# invoke 调用 Agent
from langchain.agents import create_agent
from langchain.messages import HumanMessage
from langchain.chat_models import init_chat_model
from dotenv import load_dotenv

# 1.加载环境变量
load_dotenv()

# 2.初始化模型
model = init_chat_model(
    "deepseek-v4-flash",
    extra_body={"thinking": {"type": "disabled"}},
)

# 3.定义 tool（可以没有，不过这个时候只能对话，不算完整的 Agent）
tools = []

# 4.创建智能体
agent = create_agent(
    model=model,
    tools=tools,
)

# 5.调用 Agent
result = agent.invoke({"messages": [HumanMessage("你是谁？")]})

# 6.打印结果（注意是 [-1]，不是 result['content']）
print(result["messages"][-1].content)

它和直接调模型的差别，一条条对上比较好记：

对比项model.invoke(...)agent.invoke(...)
入参str 或 list[BaseMessage]dict，形如 {"messages": [...]}
出参一个 AIMessage一个 dict
结果位置result.contentresult["messages"][-1].content
消息内容只有 AI 这一条完整历史，可能夹着 tool 消息
循环次数一次推理可能推理 → 调工具 → 再推理

一句话区分

  • Model 调用：传消息（一条或多条），返回消息（AIMessage）
  • Agent 调用：传 dict，返回 dict，AI 的回答在 messages 的最后一条

stream_events ​

从 LangChain 1.3 开始有了新的流式模式，内部叫 V3，入口是 agent.stream_events(...)。它返回一个 GraphRunStream 对象，你可以自己挑想看哪条流。

先看一眼两种等待方式的差别：

能拿到的东西：

流内容典型用途
.messages逐条、逐片段的消息文本聊天界面的打字效果
.values执行过程中 Agent state 的快照调试，看清每一步的状态
.output最终的 Agent state只要最终结果
.subgraphs子 Agent 的运行信息多 Agent 编排
.extensions自定义事件流业务埋点、自定义进度
python
# stream_events 调用 Agent
from langchain.agents import create_agent
from langchain.messages import HumanMessage
from langchain.chat_models import init_chat_model
from dotenv import load_dotenv

# 1.加载环境变量
load_dotenv()

# 2.初始化模型
model = init_chat_model(
    "deepseek-v4-flash",
    extra_body={"thinking": {"type": "disabled"}},
)

# 3.定义 tool（可以没有，不过这个时候只能对话，不算完整的 Agent）
tools = []

# 4.创建智能体
agent = create_agent(
    model=model,
    tools=tools,
)

# 5.流式调用
stream = agent.stream_events(
    {"messages": [HumanMessage(content="你是谁？")]},
    version="v3",
)

# 6.逐片段打印
for message in stream.messages:
    for text in message.text:
        print(text, end="", flush=True)
print()  # 收尾换行

参数和返回值的细节：

  • 参数 1：dict，key 为 messages，和 invoke 完全一致
  • 参数 2：version，流 API 的版本，推荐 "v3"
  • 返回的 stream 里挂着多条 event stream，stream.messages 才是消息那条
  • message.text 是这一片段的纯文本，str 类型，直接拼就行

系统提示词 ​

发给模型的所有消息都可以算提示词（Prompt），其中 SystemMessage 最关键——它设定角色和本次对话的背景，对输出风格影响很大，所以单独叫系统提示词（System Prompt）。

创建 Agent 时可以直接给 system_prompt，不用每轮自己塞一条 SystemMessage：

python
# 系统提示词
from langchain.agents import create_agent
from langchain.messages import HumanMessage
from langchain.chat_models import init_chat_model
from dotenv import load_dotenv

# 1.加载环境变量
load_dotenv()

# 2.初始化模型
model = init_chat_model(
    "deepseek-v4-flash",
    extra_body={"thinking": {"type": "disabled"}},
)

# 3.定义 tool（可以没有，不过这个时候只能对话，不算完整的 Agent）
tools = []

# 4.创建智能体
agent = create_agent(
    model=model,
    tools=tools,
    system_prompt="你是迪迦，使用迪迦的语气说话",  # 系统提示词
)

# 5.流式调用
stream = agent.stream_events(
    {"messages": [HumanMessage(content="你是谁？")]},
    version="v3",
)

for message in stream.messages:
    for text in message.text:
        print(text, end="", flush=True)

注意事项 ​

  1. 别在 dict 上取 .content。agent.invoke() 返回的是 dict，写 result.content 会直接报错，正确写法是 result["messages"][-1].content。
  2. 流式打印必须带 flush=True。print(text, end="", flush=True) 三个都要，少了 flush 输出会被缓冲，看起来像卡住一次性刷出来。
  3. 流式结束记得补一个 print()。end="" 让每次输出不换行，循环结束后不补空 print()，后面所有日志都会粘在同一行。
  4. stream_events 一定要传 version="v3"。不传就走旧版接口，stream.messages 拿不到东西。
  5. 不要每轮手动塞 SystemMessage。多轮对话时它会在历史里越堆越多，既浪费 token 又干扰模型；用 system_prompt 参数，创建时定一次。
  6. 只有工具的 Agent 才叫完整 Agent。tools=[] 时它就是个带格式的聊天机器人，模型不会自己动手，全是对话。

实战案例 ​

目标：给 Agent 装一个查时间的工具，先用 invoke 验证工具确实被调用，再换成 stream_events 看流式效果。

第一步：invoke，看清一次调用走了几步 ​

python
from datetime import datetime

from dotenv import load_dotenv
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain.messages import HumanMessage
from langchain.tools import tool

load_dotenv()

@tool
def get_now() -> str:
    """返回当前的日期和时间。"""
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")

model = init_chat_model(
    "deepseek-v4-flash",
    extra_body={"thinking": {"type": "disabled"}},
)

agent = create_agent(
    model=model,
    tools=[get_now],
    system_prompt="你是一名简洁的助理，回答不超过两句话。",
)

result = agent.invoke({"messages": [HumanMessage("现在几点？")]})

for m in result["messages"]:
    print(type(m).__name__, "→", repr(getattr(m, "content", ""))[:50])

print("最终回答：", result["messages"][-1].content)

三个观察点：

  • 中间那条 ToolMessage 就是证据：工具真的被执行了，不是模型瞎编时间
  • 第二条 AIMessage 的 content 是空的，因为它这一轮只决定调工具，还没开口说话
  • 真正的答案永远在最后一条，前面都只是过程

第二步：换成流式，体验边跑边出 ​

其余代码不动，只把最后一段换掉：

python
stream = agent.stream_events(
    {"messages": [HumanMessage("现在几点？")]},
    version="v3",
)

for message in stream.messages:
    for text in message.text:
        print(text, end="", flush=True)

对比下来能感觉到：

  • invoke 是等模型想完、工具跑完、再想完，然后整段文字一次性出现
  • stream_events 是第一个字很快就到，后面边生成边补，界面不会长时间空白

工具调用这部分照样发生，只是 stream.messages 默认只吐 AI 的文本片段，tool 消息不会混进来——所以这段流式代码可以放心直接打到终端或前端。

总结 ​

  • Agent 调用是「把活交给 Agent 自己跑一圈」：入参 {"messages": [...]}，出参 dict，答案在 messages[-1]。
  • invoke 阻塞到底，适合脚本和后台任务；stream_events 边跑边吐，适合聊天界面，别忘了 version="v3"。
  • 角色设定用 system_prompt 一次给足，别在每轮消息里堆 SystemMessage。
  • 判断这次是不是真调了工具，看返回的 messages 里有没有 ToolMessage。
  • 只有 tools 非空的 Agent，才是能动手的那个；空列表只是聊天。
