AI教程 ​

概念 ​

AI 教程这一栏，讲的不是「人工智能」这个大词，而是能被你直接用在项目和工作里的几件事：把模型理解成一个只会续写文字的黑盒，然后学会怎么喂它、怎么接它、怎么验证它。

四个先记住的名词：

名词一句话
大模型（LLM）只做一件事：根据前文预测下一个 token。对话、写代码、翻译都是这件事的副产品
提示词（prompt）你给的输入，包含角色、任务、约束、示例四类信息
上下文窗口一次请求模型能同时看到多少 token，超了就截断
token模型处理文本的最小单位，中文大致一字一个，英文一个词约 1.3 个

把它当成一个记性很好、但完全不了解你处境的实习生：交代得越具体，产出越可用；留白越多，它越会自己编。

它到底在算什么 ​

只有两段过程，别混着理解：

  • 训练：拿海量文本做「下一个词」的预测，反复调参数，把语言规律压进权重。这一步不发生在你机器上
  • 推理：加载权重，输入 token 序列，输出下一个 token 的概率分布，采样一个拼回输入，继续预测。逐 token 生成，所以耗时和费用都跟着输出长度走

这也解释了它为什么不会「查资料」：推理时它只看得到你给的那段上下文，权重里只有训练时的模糊记忆。

上下文窗口决定能记多少 ​

窗口量级大约相当于说明
4K三千字中文老模型常态，够一次问答
8K–32K六千到两万字单篇长文、一个中等代码文件
128K 以上十万字级别能塞整本手册，但中间内容容易被忽略

窗口大不等于记得牢。把关键要求在开头和结尾各说一遍，比只写在中间可靠得多。

温度和采样参数 ​

参数作用常用取值
temperature越高越随机，越低越保守事实问答 0–0.3；创意 0.7–1.0
top_p只在概率累计到 p 的词里采样保持默认，与温度二选一调
max_tokens限制输出长度按场景给上限，防止话痨
frequency_penalty抑制重复用词长文生成时给 0.1 左右

要「每次完全一致」，温度设 0 也做不到——批处理顺序、浮点误差都会带来微小差异。需要可复现时，把结果存下来，别指望重跑复现。

参数规模与显存 ​

粗算规则：每 10 亿参数约需 2GB 显存（FP16），再加上 KV Cache 和上下文长度还要涨。

模型规模FP16 显存下限4bit 量化后现实结论
7B约 14GB约 4–5GB8GB 显卡能跑量化版
13B约 26GB约 8GB16GB 显卡勉强
70B约 140GB约 40GB消费级单卡基本没戏

跑不动时，先换小模型或量化版本，再考虑换硬件。

有什么用 ​

不碰这块的代价很具体：写文档逐条翻资料、读陌生仓库一行行猜、做表格手工搬运、重复解释同一个业务背景。更糟的是把模型当搜索引擎，拿到一段通顺答案直接进生产，出错时连错在哪都说不清。

反过来，它的价值集中在四类场景：

场景解决什么
写文档、写周报、写公告从零起稿变成改稿，时间花在判断而不是打字
读代码、读报错、读陌生仓库先让它解释一遍，再自己去验证，缩短「看不懂」的时长
批量整理非结构化文本转成表格字段，省掉逐条搬运
把对话能力接进产品用 API 或 SDK 变成功能，而不是手动复制粘贴
