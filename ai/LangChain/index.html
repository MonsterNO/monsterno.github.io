LangChain ​

概念 ​

LangChain 是一个把「模型调用」拆成可组合零件的编排框架。它本身不含智能，只负责把提示词、模型、工具、检索这些东西串成一条可维护的流水线。

一句话定位：当你的流程超过两步、需要分支和重试时，别再手写胶水代码。

有什么用 ​

手写调用的代价在三个地方显形：换模型要改多处、加重试和日志要重新包一层、多步流程全挤在一个函数里没法测。

不用框架用了框架
每家 SDK 的入参格式各写一遍统一成 message 结构，换模型只改一行
重试、超时、日志手工拼用 Runnable 串起来，.with_retry() 一行加
流程写死在函数里每个环节独立可测、可替换

但也要清楚：一句提示词就能解决的事，上框架是负担。它的价值随步骤数量增长。

核心抽象 ​

抽象管什么
ChatModel一次模型调用，统一各家的消息格式
Messagesystem / human / ai / tool 四类角色，拼上下文
PromptTemplate提示词模板，变量填充
OutputParser把输出解析成 JSON 或结构化对象
Runnable可组合单元，`
Tool / Function Calling让模型决定调哪个外部函数
Retriever检索接口，RAG 的入口

一个最小可跑的链 ​

python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是严谨的技术编辑，只输出正文，不解释。"),
    ("human", "把下面这段改写成 {tone} 语气，200 字以内：\n{text}"),
])

chain = prompt | ChatOpenAI(model="gpt-4o-mini", temperature=0.3) | StrOutputParser()
print(chain.invoke({"tone": "克制", "text": "系统今晚升级，可能影响登录。"}))

| 两端只要是 Runnable 就能串，invoke 走单个、batch 走批量、stream 走流式，参数不用改。

什么情况别用它 ​

情况建议
单轮问答、格式固定直接调 SDK，少一层依赖
只做一个 RAG 检索用向量库 SDK + 一次模型调用即可
需要复杂分支、循环、人工介入上 LangGraph，普通 Chain 不够用
团队没人维护依赖树版本锁死，或用更轻的封装

注意事项 ​

现象：导入报错，提示找不到某个模块。 原因：LangChain 已拆包（langchain-core / langchain-openai / langchain-community），旧教程还在写 from langchain import ...。 解法：按厂商装独立包，模型类从 langchain_<厂商> 里导。

现象：链能跑通，但输出解析经常抛异常。 原因：模型返回带了 Markdown 包裹或多余解释。 解法：提示词里明确「只输出 JSON」，解析失败时单独走一次修复重试，而不是整条链重跑。

现象：加上工具调用后行为不稳定。 原因：工具描述太笼统，模型挑错工具。 解法：每个工具描述写清「什么时候该用它」，参数给示例值。

总结 ​

  1. LangChain 是编排框架，不提升模型能力，只降低多步流程的维护成本
  2. 换模型只改一行，靠的是统一的 message 抽象
  3. 单个调用别上框架，步骤超过两步再考虑
  4. 已经拆成多个包，按厂商装对应依赖，别照抄旧 import
  5. 需要分支、循环、人工介入时，往 LangGraph 走，不要硬拼 Chain
  6. 结构化输出必须配「只输出 JSON」+ 解析失败单独重试
